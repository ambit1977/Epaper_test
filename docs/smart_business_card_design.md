# スマートビジネスカード 仕様書

E-Paper（表面：名刺情報、日替わりトピック）+ NFC（裏面：vCard、URL、交換時の状況メモ）を
持ったデジタル名刺デバイスの設計。

## 1. コンセプト

```
┌──────────────────────────┐   ←  表面（E-Paper 4.2")
│                          │       名前、肩書き、会社
│   Taishi Akiyama         │       連絡先 QR コード
│   ezmag                  │       「今日のトピック」「最近の活動」
│   Engineer / Designer    │       など日替わり情報
│                          │
│   [QR]   "今日は..."      │
└──────────────────────────┘

┌──────────────────────────┐   ←  裏面（NFC アンテナ + IC）
│                          │       スマホタッチで:
│   📡 NFC                  │       - vCard を連絡先に追加
│                          │       - ポートフォリオ URL を開く
│                          │       - 受け取り時の日時 / 場所が
│                          │         vCard NOTE に自動記入される
└──────────────────────────┘
```

### 普段の動作
- ESP32 が定期的に WiFi 接続して時刻 / 場所 / 今日のトピックを更新
- E-Paper 表面に最新情報を描画
- NFC タグの vCard も毎回書き換え（NOTE フィールドに日時 / 場所を反映）

### 名刺交換時
- スマホをかざすだけで vCard 受信
- 受け取った相手のスマホには「2026-05-27 17:30 / Tokyo - "IoT について話しました"」が NOTE として残る
- ESP32 の電源が OFF でもパッシブ動作で読み取り可能

---

## 2. 選定部品（NFC 追加分）

### NFC IC
- **NTAG I²C plus 2k** (NT3H2111W0FTT) ✓ 確定
  - EEPROM: 1912 byte
  - I2C インターフェース
  - パッシブ動作対応（ESP32 OFF でもスマホで読める）
  - Field Detect (FD) ピン: スマホかざしを ESP32 が検知可能

### モジュール選定
| 候補 | 仕様 | 入手 |
|------|------|------|
| **ELECHOUSE NTAG I2C plus board** | アンテナ付き、I2C 直出し | AliExpress |
| **Adafruit NTAG I2C plus Breakout** | 公式、ライブラリ完全対応 | Adafruit |
| **チップ単体 + 自作アンテナ** | 完全カスタム | Mouser + ケース印刷時にコイル |

→ **Adafruit のブレークアウト** がライブラリ・サンプル豊富で推奨。

### NFC 用磁性シート
- **フェライト NFC シート**（厚み 0.3mm 程度）
- アンテナと E-Paper 金属層の間に挟む
- Amazon、AliExpress で 300-500 円

```
  │ (表面)   │◀──▶│              │◀─▶│   (裏面)       │

                         │                   │

                         ▼
              WiFi / NTP / API
```

### 配線追加（既存のベアモジュール構成に対して）

| 信号 | ESP32 GPIO | NTAG I²C plus |
|------|-----------|---------------|
| VCC | 3.3V | VCC |
| GND | GND | GND |
| SDA | GPIO21 | SDA |
| SCL | GPIO22 | SCL |
| FD (割込) | GPIO13 | FD |

注意：GPIO21/22 は ESP32 のハードウェア I2C デフォルトピン。

## 4. ケース設計への影響

### NFC アンテナと E-Paper の干渉対策

```
┌──────────────────────────────────┐ ← 名刺ケース 全体 (130×95×18mm)
│                                  │
│   ┌──────────────────────────┐   │ ← 前面: E-Paper 4.2"
│   │                          │   │
│   │   [E-Paper パネル]       │   │   ガラス面が表に
│   │                          │   │
│   └──────────────────────────┘   │
│   ↑ E-Paper 領域                  │
│                                  │
│   ── フェライトシート ──         │ ← E-Paper 金属層を遮蔽
│                                  │
│   ── ESP32 ベアモジュール基板 ── │
│   ── LiPo バッテリー ──          │
│                                  │
│   ──────────────────────────     │
│                                  │
│   [NFC アンテナ]                 │ ← 裏面下部、E-Paper 領域外
│                                  │
└──────────────────────────────────┘
```

### 推奨配置

- **アンテナはケース裏面の下部** (E-Paper パネルの直下に重ねない)
- **E-Paper との間にフェライトシート** を挟む
- アンテナとパネルの距離: **3mm 以上**
- 配線で I2C を引き回す（フレキ or リード線）

### サイズ影響

- 厚みが 1mm 程度増える可能性（フェライトシート + 配線）
- 寸法目標: 130 × 95 × **19mm** (元 18mm から +1mm)

## 5. NDEF メッセージ仕様

NFC タグに書き込む内容は NDEF (NFC Data Exchange Format) で記述。

### メッセージ構成（3 レコード）

```
[NDEF Message]
  │
  ├── Record 1: vCard (MIME type: text/x-vcard)
  │   BEGIN:VCARD
  │   VERSION:3.0
  │   FN:Taishi Akiyama
  │   ORG:ezmag
  │   TITLE:Engineer
  │   EMAIL:ambit.akiyama@gmail.com
  │   TEL:+81-90-XXXX-XXXX
  │   URL:https://example.com
  │   NOTE:2026-05-27 17:30 / Tokyo - "IoTについて話しました"
  │   END:VCARD
  │
  ├── Record 2: URI (Portfolio)
  │   https://portfolio.example.com
  │
  └── Record 3: URI (LinkedIn / SNS)
    https://linkedin.com/in/...
```

### NOTE フィールドの動的更新

ESP32 が起動するたびに、以下を組み立てて NOTE に入れる：

```
{時刻 (NTP)} / {場所 (WiFi SSID 等から推定)} - "{今日のトピック}"

例:
  "2026-05-27 17:30 / 渋谷オフィス - "省電力 IoT について話しました""
  "2026-05-27 19:00 / 銀座ミートアップ - "LiPo + ESP32 の話""
```

## 6. 「場所 / トピック」のデータソース

### 場所推定

最もシンプルで実用的なのは **WiFi SSID マッピング**：

```cpp
struct Location {
  const char* ssid;
  const char* display_name;
};

const Location LOCATIONS[] = {
  {"NOANOA",         "自宅"},
  {"ezmag-office",   "渋谷オフィス"},
  {"FREESPOT",       "外出先"},
  {"Starbucks_Wi2",  "スターバックス"},
  // ...
};
```

接続できた SSID で「場所」を決定する。

将来的に：
- IP geolocation API（位置精度は低い）
- BLE ビーコン
- ULP コプロセッサで定期スキャン

### 今日のトピック

選択肢：
1. **設定ファイル**（一番シンプル）
   - `config.h` に1日分のトピックを書く
   - 朝にスマホで NFC 書き込みして更新（書き込み機能を持ったスマホアプリで）

2. **クラウド経由**
   - 自分の Web サーバーに置いた JSON を ESP32 が取得
   - スマホでブラウザから内容更新できる

3. **Google Calendar 連携**
   - 当日の予定タイトルをトピックとして使う
   - OAuth 認証が必要、やや複雑

実用的なのは（2）「自分のクラウド経由」。Cloudflare Workers + KV や、GitHub Gist など。

## 7. ESP32 の動作フロー

```
[Power on / Deep Sleep wake]
       │
       ▼
[WiFi 接続]
       │
       ├──→ SSID 判定 → 場所決定
       │
       ▼
[NTP 同期]（必要時のみ）
       │
       ▼
[API 取得]
   ├── 天気 (Open-Meteo)
   └── 今日のトピック (自分のクラウド)
       │
       ▼
[E-Paper 描画]
   ├── 名前、肩書き
   ├── 天気（小さく表示）
   └── 今日のトピック
       │
       ▼
[NDEF 構築]
   ├── vCard (NOTE = "今日時刻 / 場所 - トピック")
   ├── ポートフォリオ URL
   └── SNS URL
       │
       ▼
[NTAG I²C plus に書き込み (I2C)]
       │
       ▼
[WiFi OFF, Deep Sleep N 分]
```

### FD ピン割込み（スマホタッチ検知）

NTAG I²C plus の FD ピンはスマホがタッチした瞬間に Low になる。
これを GPIO13 で監視して、ESP32 がカウント / 記録できる。

応用：
- 「今日 3 人と名刺交換」を E-Paper 表面に表示
- 直近の交換時刻を記録
- Wi-Fi 経由で「交換ログ」を自分のクラウドに送信（CRM 的用途）

## 8. ライブラリ

| ライブラリ | 役割 |
|-----------|------|
| **Adafruit_PN532** | ❌ これは PN532 リーダー用、NTAG とは別 |
| **don/NDEF** | NDEF メッセージ生成、汎用 |
| **electroniccats/NTAG_I2C_plus** | NTAG I²C plus 専用 driver |
| **NXP-NFCReaderLibrary** | NXP 公式、本格派、Arduino 移植は手間あり |

シンプル実装としては：
- I2C で生のレジスタアクセス + NDEF を手書きで構築するのが一番軽い
- 必要なら don/NDEF ライブラリで補助

## 9. 実装段階

### Phase 1: 静的 NDEF（最小動作確認）
- 起動時に固定の vCard を書き込み
- スマホで読み取れるか確認

### Phase 2: 動的 NOTE（時刻 / 場所付与）
- NTP 時刻と WiFi SSID から NOTE を生成
- 毎回起動時に書き換え

### Phase 3: トピック連携
- 自分のクラウドから「今日のトピック」を取得
- vCard NOTE と E-Paper 表面に反映

### Phase 4: FD 割込み活用
- スマホタッチを検知してカウント
- 表面にカウント表示
- ログをクラウドへ

## 11. 配信プロセス（運用イメージ）

朝の所作：
1. ケースを充電器から外す
2. 自宅 Wi-Fi に接続 → 場所「自宅」、時刻 7:30
3. クラウドから「今日のトピック」取得（出かける前にスマホで更新済み）
4. E-Paper 表示が更新される
5. NTAG にも「2026-05-27 07:30 / 自宅 - "今日は○○の話しよう"」と書き込まれる

ミーティング前：
1. オフィス Wi-Fi に接続 → 場所「渋谷オフィス」
2. 10分ごとに NTAG の NOTE が更新される
3. 相手にカードを渡す → スマホタッチ → vCard 取得
4. 相手のスマホに「渋谷オフィスで会った」が NOTE として残る

帰宅：
1. USB-C を充電器に挿す
2. リポが充電される
3. 翌日も使える

## 12. リスクと対策

| リスク | 対策 |
|-------|------|
| アンテナと E-Paper の干渉で読めない | フェライトシート挟む、距離取る、E-Paper 領域外にアンテナ配置 |
| NDEF メッセージが 2KB を超える | URL を短縮 URL に、写真は URL でホスト |
| トピック更新が遅れて古い情報のまま | 起動時に必ず取得試行、失敗時は前回値を保持 |
| 場所推定ミス（同じ SSID が複数地点） | BSSID も保存、または手動上書き機構 |
| NTAG への書き込み失敗 | 書き込み後にベリファイ、失敗時はリトライ |
